# DSH 改造待办

日期：2026-10-29。备注，未实现。

这是**后续改造 DSH / 工程基建**的缺口，不是影子插件的内核待办。影子线三条不在这里重复：

| 优先级 | 在哪 | 管什么 |
|---|---|---|
| P0 验证优先闭环 | [DESIGN.md](../DESIGN.md) §11、[README.md](../README.md)「影子线待办」 | 完成闸门与验收证据；影子只派活 + inspect |
| P1 工作项状态面 | 同上 | 状态面留在影子包外 |
| 影子内置记忆 | 同上 | 只记影子域（派活、验收、决策上下文） |

**边界（整份都适用）**：状态面、通用账本、项目级双记都不进影子内核，也不作为 `dsh-plugin-shadow` 的依赖。影子继续只做派活，并用 inspect 看结果；影子域记忆另计，见 DESIGN §11。

## P2 — 双重记忆落地（选型 / 配置）

**优先级**：P2。

**缺什么**：项目级通用记忆还没有一份选定并配上的双记方案。影子域（派活、验收、决策上下文）归影子内置记忆；项目 MEMORY / PROGRESS 这一层还没有落地。

**可复用**：社区已有的双记方案（或等价物），以及 DSH 自己的记忆机制。项目级走这两条里选定的一条，不新造第三套账。

**建议怎么补**：在 DSH / 项目侧选型，装上一个社区双记方案，配成项目级通用记忆的读写路径。装在 DSH 或项目上。

**边界**：不作为影子依赖，不并进影子包。影子内置记忆继续不管项目 MEMORY / PROGRESS 的全站双记（DESIGN §11）。状态面和通用账本也不借这次选型塞进影子内核。

## P3 — 强制改码后测 / 格式化

**优先级**：P3。

**缺什么**：项目级没有「编辑之后必须跑测试和格式化」的闸门。测试或格式化失败了，改动仍能继续往下走。

**可复用**：DSH 的项目级 Hooks。

**建议怎么补**：加项目级 Hooks，编辑结束后必跑 test 和 format。失败则 steer（拉回重做）或 deny（拒绝这一步）。

**边界**：这是项目工程闸门，时刻在「改完代码」。影子线 P0 是另一道闸：任务 `complete` 必须带验收证据，证据与闸门用 **dsh-verification**（或等价），不在 rd-shadow 里自造验证引擎。两道不要并成影子内核里的一个账本。

## P4 — 瘦主指令 + 按需规则工程包

**优先级**：P4。

**缺什么**：主指令过厚，路径级规则没有一份可复制的模板。新项目要手写一整套才能开工。

**可复用**：DSH 的主指令与 path rules。

**建议怎么补**：做一份 bootstrap 工程包。主指令只留极瘦的总则，具体约束放进按路径生效的 path rules 模板。新项目从这份模板复制，不从一份长指令抄起。

**边界**：模板放在 DSH / 项目工程侧。不把规则引擎做进影子包。

## P5 — 标准流程 Skills 正文

**优先级**：P5。

**缺什么**：理解 → 计划 → 写码 → 测 → 审 → 更新记忆，这六步没有可复用的 Skills 正文。每条线都在临场重写。

**可复用**：DSH Skills。

**建议怎么补**：把这六步写成一份可复用的 Skills，项目直接引用。其中「更新记忆」写入项目级通用记忆（P2 选定的那套），不写入影子包。

**边界**：Skills 是工程流程正文。不把项目双记、状态面或通用账本带进影子内核。

## P6 — 端到端一键可检查

**优先级**：P6。排在 P2–P5 之后：它把前面几件收成一次可重复的安装和自检，不替代其中任何一件的选型。

**缺什么**：影子、验证、记忆、hooks、skills 和依赖升级还不能一次装齐，也没有一条自检回答「这套基建是否按各自的边界接上」。

**可复用**：

- 影子：派活 + inspect（rd-shadow 现有能力）
- 验证：社区 **dsh-verification**（或等价），对应影子线 P0，不在影子包内自造
- 记忆：P2 的项目级方案，加上影子域内置记忆（DESIGN §11）
- Hooks：P3
- Skills：P5
- 升级：**Renovate**

**建议怎么补**：收成一份可重复的 bootstrap，并带自检。自检只核对各件在位、接线符合本文件和 DESIGN §11 的边界。依赖升级交给 Renovate。

**边界**：不做 Hub。不自研宿主探针，也不做升级红灯。自检不把状态面、通用账本、项目双记并进影子包。
